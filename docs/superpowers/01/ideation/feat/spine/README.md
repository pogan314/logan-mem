# feat/spine

- A **spine** is a map of a codebase: which files and modules exist, what each is for, what calls what. An agent reads it to orient before touching code.
- The owner's words: "I do want the spine to be possibly in the actual repo branch so we can have notes and descriptions and shit. It should probably be its own separate system within the monorepo."
- The old build did the opposite: a SQLite file in a cache folder (`/home/ubuntu/.pogan/cache/spine/`), wiped and rebuilt every time, no place for a human note.

## The idea

| Property | Old build | logan-mem idea |
|---|---|---|
| Where | `~/.pogan/cache/spine/<id>.db` (throwaway) | A committed file in the repo, e.g. `.logan-mem/spine.md` (or one file per top-level module) |
| Format | SQLite, unreadable without the tool | Markdown with YAML per module — readable on GitHub, diffable, reviewable in a PR |
| Lifecycle | `DELETE FROM files` then full rebuild | Regenerated by **merging**: the tool updates the machine-derived parts (files, symbols, call edges) and never touches the human parts |
| Human notes | None | `note:` / `purpose:` / `gotchas:` fields per module that a person or agent fills and that survive regeneration |
| Branches | One cache, all branches | Each branch carries its own copy; merges resolve like any text |
| Subsystem? | Tangled into memory search | Its own small subsystem: a generator, a file format, one read tool. Memory may *link* to spine entries; it does not own them |

## What goes in one spine entry (sketch)

```yaml
- path: src/capture/stop-hook.ts
  kind: module
  exports: [runStopCapture, writeMemoryFile]
  calls: [src/store/write.ts, src/store/dedupe.ts]
  called_by: [hooks/hooks.json → Stop]
  # ---- human / agent notes below survive regeneration ----
  purpose: Turns the end-of-session reflection into memory files.
  note: Keep this under 150 lines; it is the path that must never break.
  gotchas: Runs inside a hook timeout; no network calls here.
```

- The machine part is what tree-sitter (a fast code parser) can derive: files, exported symbols, import/call edges. Aider's `repomap.py` and codebase-memory-mcp both do this; see the wiki.
- The human part is the value. A spine without notes is just `ls -R`.

## Version placement

- Likely version 02. It is the feature most likely to balloon (the old build's spine + doc-pairs + modules + html render was thousands of lines).
- Version 01 could ship a **hand-written** spine file for logan-mem itself, with no generator, to learn which fields actually get used. That costs nothing and tests the format.
